# 《Git 的概念地图》——用自然语言驾驭版本控制

> **一本不背命令的 Git 书。** 帮你建立 Git 的概念地图（仓库、提交、分支、远程、历史五张地图），再用自然语言指挥 AI 帮你执行。
>
> 如果你对 Git 的使用停留在「复制 Stack Overflow 命令 → 祈祷不出错」的循环里，这本书就是为你写的。

## 这本书讲什么

市面上几乎每本 Git 书都是同一种写法：按命令组织，`add` / `commit` / `push` 一章章过。结果是读者背下几十条命令，遇到问题依然不知道该用哪条。

本书反过来。**先用概念组织，再让 AI 执行命令：**

1. **五张概念地图**：仓库（自包含的历史数据库）、提交（不可变快照）、分支（会移动的书签）、远程（会呼吸的镜子）、历史（可重串的项链）——用「项链-珠子-标签」一套比喻贯穿全书，一次讲透，全书复用。
2. **场景判断优先**：每个 Git 动作前先回答「这该不该做」——该开分支还是直接提交？该 merge 还是 rebase？该 push 还是先 fetch？判断清楚了，命令让 AI 来敲。
3. **AI 指令一等公民**：全书每一章都有「AI 指令箱」——可直接整段复制的自然语言指令模板，配 🟢/🟡/🔴 红黄绿安全分级。Claude Code、Cursor、Copilot、Aider、Windsurf 通用。
4. **事故恢复专章**：Git 几乎不扔东西——reflog、bisect、cherry-pick、gc 的 30 天托管期，8 个灾难剧本逐个拆解恢复路径。

## 谁适合读

- 用了几年 Git 依然概念模糊、靠肌肉记忆硬撑的开发者
- 想用 AI 编码工具（Claude Code / Cursor / Copilot）但只会让它「fix bug」的开发者
- 需要给团队制定 Git 规范的技术管理者（第 7、12 章可直接落地）

## 这本书不讲什么

- **不讲命令背诵**——命令在本书是侧栏小字，附录 A 才有速查表
- **不讲 GUI 工具**——SourceTree / TortoiseGit 有自己的说明书
- **不绑定任何 AI 产品**——指令模板与工具无关，随产品迭代不会过时

## 阅读顺序建议

**第一次读**：先读第 0 章自测（10 道题），再看概念地图五连（第 1-5 章），然后按需跳场景章。

**AI 指令即查即用**：附录 B 收录全书 157 条提示词模板，按「发布前检查 / 历史整理 / 事故恢复 / 陪练模式」等 13 类场景分组。
