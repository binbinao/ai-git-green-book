## 一、封面文案

### 1.1 主书名（沿用，建议不改）

> **Git 的概念地图**

理由：四个字 + 一个名词短语，与全书的核心隐喻（地图）完全一致，且与市面上所有
"Git 从入门到精通 / Git 实战 / 循序渐进学 Git"形成语域区分。**不建议改成"Git 不需要背命令"这类句式**——
后者是一次性钩子，会被读者当作鸡汤书名，而"概念地图"是全书真正的结构承诺。

### 1.2 副标题（三选一）

| 方案 | 文案 | 适用场景 | 取舍 |
|---|---|---|---|
| **A（推荐）** | **用自然语言驾驭版本控制** | 保留现状 | 与正文的 AI 分工主张完全一致；缺点是不够"钩" |
| B | **不背命令，照样把事情做对** | 面向泛技术读者、电商详情页 | 更钩人，但把书定位成"反智"型，与书中"概念比命令更重要"的严肃主张有偏差 |
| C | **给 AI 时代的 Git 心智模型** | 面向 AI 工具用户（Claude Code / Cursor 群体） | 精准命中增量读者，但会把传统 Git 读者挡在门外 |

**推荐 A**，并在**腰封**上再用 B 的句式做钩子——这样封面保持严肃、腰封负责传播。

### 1.3 封面核心句（放在封面下沿或勒口）

> **珠子不可变，项链可塑。**
> **Git 里没有"改历史"，只有"造新珠子 + 挪名牌"。**

理由：这两句是全书最凝练、最可引用的两句话（分别出自第 5 章与全书总图），
读者看完能立刻向同事复述——这是"可记忆模型"这一标从 4 分继续往上走的抓手。

### 1.4 封底文案（约 180 字）

> 你可能已经用了好几年 Git，能熟练敲出 `git commit`、`git push`、`git rebase --abort`，
> 但每次看到 `CONFLICT` 还是会心跳加速——因为你不确定它到底在做什么。
>
> 这不是你的问题。**市面上大多数 Git 书都按命令组织**，你背下了几十条命令，
> 遇到新情况依然不知道该用哪条。
>
> 这本书反过来：**先讲清楚 Git 到底是什么**——仓库是一个自包含的档案馆，
> 提交是不可变的珠子，分支只是挂在珠子上的名牌，历史是一条可以重串的项链——
> 然后教你用自然语言把这些事交给 AI 去做。
>
> 全书 15 章 + 4 个附录，每一个 Git 动作都先回答"这该不该做"，再回答"怎么做"。
> 配 17 张概念图、8 个事故恢复剧本、一整套可直接复制的 AI 指令箱，
> 以及一个贯穿全书的安全分级：🟢 放心让它做 · 🟡 先看方案 · 🔴 你自己按快门。

> **合规自查**：以上 180 字无极限词、无效果承诺、无第三方评价、无数据断言。
> 唯一带数字的"17 张概念图 / 8 个事故剧本"均为**本书自身的可核验事实**。

> **binbinao**，软件工程师。
